# RELOOP MRF 可回收物分拣中心数字孪生

面向客户交流的可回收物分拣中心三维数字孪生：一座完整厂房、两条分拣线、四类可回收物、进出货双向物流，以及按约 130 秒班次无缝循环的全流程动画。设备可点选查看状态与读数，参数干预默认关闭、开启后真实改变仿真结果。

[在线演示（GitHub Pages）](https://yuhaoxiong.github.io/recycling-mrf-digital-twin/)  · [完整复现提示](./docs/RECREATE_PROMPT.zh-CN.md) · [发布验证记录](./docs/VALIDATION.md)

[桐乡实际产线运行动画](https://yuhaoxiong.github.io/recycling-mrf-digital-twin/actual.html)：基于实际 CAD 和已确认的 17 台设备工艺，提供独立动画、料仓联锁与共用打包流程。原演示保持独立，详见[实际产线说明](./docs/ACTUAL_ANIMATION.md)。

**这是面向客户的概念演示，不是分选设备的控制或监控系统。** 所有产能、识别率、节拍、吨位都是演示设定；光学分选与高光谱识别不接真实传感器、模型或 PLC / MES / WMS / 称重系统；机械臂抓取是动画概念，不是运动学或抓取力学仿真；叉车按预设航点行驶，没有自动调度、实时避障或碰撞物理。

## 功能亮点

- **一条塑料瓶线**：震动上料机打散瓶料包 → 爬坡机抬升并单层化 → 光选机 #1 识别 PET 气吹分流 → 光选机 #2 识别 HDPE 气吹分流 → 输送带把三路（PET / HDPE / 尾料）送入对应料仓 → 料仓达阈值后压缩打包机压成瓶砖。两级光选的次序不可颠倒：先分 PET，再分 HDPE。
- **一条纺织品线**：上料平铺机构把织物摊成单层 → 高光谱分选设备按材质（棉 / 涤纶 / 混纺）给出目标料仓 → 机械臂分选流水线逐件抓取投放；无法识别的物料从尾料口转入杂项区。
- **纸板与杂项**：不进入分拣线，只体现为存储区的堆存、打包与转运，进出量计入库存与台账。
- **双向物流**：进货货车 A 运来塑料与纺织料包、转运货车 B 运来纸板与杂项并回程装走杂项、出货货车 C 在出货月台装走全部成品打包块后过磅离场。两台叉车按各自责任区搬运，跨区必须通过**单行主通道**，同一时刻只允许一台进入。
- **设备点选**：左侧列表、三维场景与右侧详情三处联动；每台设备给出状态（运行 / 等待 / 待机 / 报警 / 已停机）、实时读数、上下游关系与工艺说明。
- **分层控制**：默认只读；开启「干预模式」后才能修改带速、给料速率、识别阈值、气吹压力、抓取节拍、打包周期与料仓阈值，改动会**真实影响**后续仿真（例如把气吹压力降到 2 bar，瓶料会开始落入尾料区）。
- **异常演示**：光选误判、料仓满溢预警（把报警线提前一包）、紧急停机三个开关，可一键演示异常与恢复；开关在暂停状态下也会立即反映到状态与报警上。
- **生产看板**：顶栏给出当日进料 / 出货量、回收率、运行设备数与班次进度；右侧看板给出分品类进出存、料仓水位条（含阈值与预警线刻度）、本班次打包数与叉车趟数、搬运任务列表、转入杂项的尾料包数、丢失计数（应恒为 0），以及近 7 日进出货趋势（演示数据）。
- **时间轴**：约 130 秒一个班次无缝循环，可拖动到任意时刻、可 1/2/4 倍速、可暂停复位，八个里程碑（进货车辆入场 / 塑料来料上线 / 首次光选分选 / 纺织来料上线 / 首件打包 / 首件成品装车 / 转运车离场 / 出货过磅）可直接点击跳转到该时刻；后台标签页不推进也不补算；系统偏好「减少动态效果」时默认暂停。
- **相机**：默认「自由视角」，打开即可拖动旋转、滚轮缩放（竖屏会按宽高比自动拉远，整块沙盘入画）；「俯瞰全厂」一键回到标准机位，「跟随选中设备」把机位推到所选设备近景。三种视角可随时切换，自由视角下不抢用户的镜头。
- **响应式**：宽屏三栏并排（设备列表 / 场景与时间轴 / 详情与看板）；≤1180 px 时右侧面板移到场景下方；≤820 px 时三块纵向堆叠、由页面统一滚动。里程碑标签会按导轨实际宽度自动错行，相机按钮浮在画布左下角，任何宽度下都不会出现按钮压时间轴或标签互相压字。

## 运行方式

使用 Node.js 22 或更新版本，以及支持 WebGL 的现代浏览器。

```sh
cd recycling-mrf-digital-twin
npm install
npm run dev
```

打开终端提示的地址即可（默认 **http://127.0.0.1:5310/**，实际产线在 **/actual.html**）。

以终端实际输出的地址为准；不要直接双击 `index.html`，请用 HTTP 访问。安装依赖需要网络，**安装构建完成后页面运行不需要任何 CDN、在线模型、在线字体或第三方接口**。

> **端口为什么不是 5173**：Windows 上 Hyper-V / WSL / Docker 会整段保留端口（本机保留了 `5141–5240`，导致 Vite 默认的 5173 直接报 `listen EACCES`）。因此把默认端口定在保留区之外的 `5310`（预览 `5311`，实际产线开发 `5320`）。可这样确认本机保留区间：
>
> ```powershell
> netsh interface ipv4 show excludedportrange protocol=tcp
> ```
>
> 若 `5310` 也被占用，用 `npm run dev -- --port 4310` 临时换一个即可。

```sh
npm run typecheck   # vue-tsc -b：含 .vue 单文件组件的完整类型检查
npm test            # Vitest + @vue/test-utils：仿真不变量、场景几何、整机联动、UI 组件、发布产物自包含
npm run build       # vue-tsc -b && vite build → dist/
npm run preview     # 预览构建产物（http://127.0.0.1:5311/）
```

两个入口的构建与预览：

```sh
npm run dev:actual     # 实际产线开发服务器（http://127.0.0.1:5320/actual.html）
npm run build:actual   # 构建到 dist-actual/（需先 npm run build）
npm run preview:actual # 预览（http://127.0.0.1:5321/actual.html）
```

`dist/` 是已提交的静态产物，使用相对 Vite base（`base: './'`），可以直接作为独立站点的根路径，也能挂到任意子路径下（例如放在另一个静态服务的子目录里）。

## 技术栈

Vue 3.5（Composition API + `<script setup>`）、TypeScript、Vite 6、Three.js 0.177；Vitest 与 `@vue/test-utils` 用于逻辑、几何与组件回归。三维层直接使用原生 Three.js 命令式 API（由 `scene/SceneHost.ts` 封装渲染器、相机、光照、IBL、拾取与帧循环），不再依赖 React Three Fiber / Drei / postprocessing。

> **重构说明（refactor 分支）**：本项目原以 React 19 + React Three Fiber 实现，现已整体迁移到 Vue 3 Composition API。迁移的取舍与验证结论见 [`docs/REFACTOR_VUE.md`](./docs/REFACTOR_VUE.md)。

全部几何为程序化生成的基础体，纹理由 `scene/textures.ts` 在运行时用 Canvas2D 画出来（混凝土地坪、彩钢瓦、橡胶皮带、纸板、木托盘、警示斜纹、文字贴花），环境光用 three 自带的 `RoomEnvironment` 经 PMREM 预卷积，界面使用系统字体回退——**没有任何外部图片、模型或在线字体**。设备同时给出中文工艺名、英文缩写（如 `NIR-1`）与英文全称，便于对照真实厂区的位号表。

## 仿真与不变量

整个演示是**时间与干预日志的纯函数**：状态只沿固定步长（1/30 s）前进，因此

- 暂停不改变轨迹，倍速只是每帧推进更多步，拖动时间轴回到任意时刻都得到完全相同的现场；
- 干预以「发生时刻 + 设备 + 参数 = 值」记入日志，重放时在记录时刻生效；拖到干预之前，历史状态自然还原；清除干预即回到默认轨迹；
- 一个班次是**闭环**：结束时全部物料都已随打包块或回程车辆出厂，料仓、存储区、任务队列全部清空，车辆离场、叉车回到起始位——所以循环播放不会出现漏料或视觉跳变。

关于闭环，有一处需要明说的**演示约定**：默认参数下现场在班末之前就已经自然清空，测试对此有断言；但如果通过干预把给料速率、带速或抓取节拍调得很低，一班之内无法处理完所有来料，此时 118 s 起的「班末清场」会把仍在厂内的物料一次性计入出场（日志会记录这一事件），以保证循环无缝衔接。这是为了让循环演示不出现残留，不是真实工厂的行为。

`tests/simulation.test.ts` 与 `tests/replay.test.ts` 把这些性质写成断言，包括：物料守恒（收到的每一包要么在厂内、要么已出厂，误差 0，丢失计数恒为 0）、料仓容量有界、只在阈值或班末清仓触发打包、PET 必须先于 HDPE 被分出、降低气吹压力只会把瓶料变成尾料而不会让物料消失、单行主通道互斥且确实发生过等待、两台叉车永不同位、同一步数状态完全一致、暂停/倍速/重置/拖动/带干预重放结果一致、默认参数下无需清场即闭合、极端干预与紧急停机下班次仍能收尾、看板每一行「进料 = 出货 + 在厂」、第二个班次与第一个班次逐位一致。

## 验证与边界
